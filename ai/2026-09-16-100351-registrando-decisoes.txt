  O que falta é só o item bônus: registrar as decisões/trade-offs. É isso que

  Decisões que identifiquei (com o "porque X não Y")

  Impostas pelo PRD, não escolha livre: NestJS, Zod (front e back), CSS Modules,
  monorepo pnpm, sem auth/pagamento/DB persistente/docker/deploy.

  Decisões técnicas reais, com trade-off explícito:

  1. Idempotência via header Idempotency-Key + store em memória, em vez de
     confiar só em desabilitar o botão no front. O motivo documentado na sessão
     3: o botão trava clique duplo, mas não cobre um retry após timeout/erro de
     rede — se a API processou e só a resposta se perdeu, o retry duplicaria a
     compra. Decisão explícita de não usar Redis (fora de escopo do PRD, projeto
     de instância única).
  2. Checagem+decremento de estoque no mesmo bloco síncrono (sem await no meio)
     em vez de um lock explícito — apoiado na garantia de que o event loop do
     Node não intercala chamadas concorrentes nessa janela. Testado com 10
     requisições simultâneas contra estoque de 5 (resultado: exatamente 5/5).
     Trade-off registrado: deixa de valer se o checkout virar assíncrono
     (gateway de pagamento) ou multi-instância.
  3. Falha de negócio libera a chave de idempotência (release) em vez de guardar
     o erro — decisão consciente para não prender o cliente a um 409 que pode
     não ser mais verdade (ex.: reduziu a quantidade). O in-flight como estado
     observável hoje é teórico (tudo é síncrono), mas mantido pensando num
     checkout futuro assíncrono.
  4. Mismatch de fingerprint vira 422, não 409 — separa "chave reciclada para
     outro pedido" (erro de cliente) de "estoque insuficiente" (conflito de
     negócio).
  5. Taxonomia de erro no client 
     (network/timeout/unavailable/http/invalid-response) com flag retryable —
     decisão de tratar 502/503/504 sem tentar ler o corpo (geralmente HTML de
     proxy) e de nunca deixar TypeError/ZodError vazar cru para a UI.
  6. Proxy do Vite sintetiza 502/504 com corpo JSON em dev — para conseguir
     testar a UI de indisponibilidade sem precisar derrubar a API de verdade,
     espelhando o que um reverse proxy real devolveria.
  7. Validação de .env com Zod + early return no bootstrap(), em vez de deixar a
     API crashar com stack trace — decisão confirmada explicitamente ("falhar
     sempre" quando .env ausente/inválido).
  8. Sem teste de componente React (jsdom/Testing Library) — a lógica de decisão
     de idempotência foi extraída para idempotency.ts como função pura
     testável; BuyForm/App foram verificados manualmente no navegador em vez de
     via teste automatizado. Trade-off real: não há regressão automática de UI.
  9. Vitest em vez de Jest — não foi escolha, foi descoberta em runtime (Nest
     CLI atual já gera com Vitest por padrão); documentado como ajuste, não
     decisão de design.

  Há também decisões "de scaffold" sem racional registrado nas sessões — ex.
  oxlint em vez de ESLint veio pronto do create-vite/nest new e nunca foi
